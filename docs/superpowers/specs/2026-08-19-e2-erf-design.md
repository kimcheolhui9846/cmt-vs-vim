# E2 — Effective Receptive Field 정량 측정 설계

2026-08-19. 전체 실험 설계는 `2026-08-18-cmt-vs-vim-experiments-design.md`에 있고,
이 문서는 그중 E2를 구현 가능한 수준까지 좁힌다.

## 검증 대상

논문 3.1절: **"CMT의 ERF는 2D Gaussian-like, Vim의 ERF는 1D scan 방향에 정합된
anisotropic"**

현재 논문은 이 주장을 그림 없이 서술로만 편다. E2는 "이방성"을 숫자로 정의해
재고, 그 숫자를 3.1절에 넣는다.

## 사전 등록 예측

측정 전에 적고 커밋한다. 결과를 보고 주장을 고쳐 쓰는 것을 git 이력이 막는다.

| 모델 | 비등방 지수 | 주축 | 수직/수평 감쇠비 |
|------|-------------|------|------------------|
| CMT-S | 1.0 ~ 1.2 | 무의미 | ≈ 1.0 |
| Vim-S | > 1.3 | 수평(scan 방향)에 정렬 | > 1.0 (수직이 더 가파름) |
| DeiT-S | ≈ 1.0 | 무의미 | ≈ 1.0 |

**예측이 빗나가는 것도 결과다.** 특히 Vim이 등방으로 나오면 논문 3.1절을 고쳐야
하며, 그것이 이 저장소가 존재하는 이유다.

### 양방향 scan에 대한 반론을 미리 막는다

Vim은 forward + backward 양방향 scan을 쓴다. 그래서 **좌우** 비대칭은 상쇄된다.
그러나 row-major flatten에서 수직으로 인접한 픽셀은 시퀀스상 W만큼 떨어지므로
**수직/수평** 비대칭은 양방향으로 상쇄되지 않는다. 세 번째 지표(수직/수평 감쇠비)가
이 지점을 정확히 겨냥한다. "양방향이라 괜찮다"는 반론에 답할 수 있는 것이 이
실험의 값어치다.

## 측정 파이프라인

해상도는 **224²만** 쓴다. 사전학습 가중치가 유효한 해상도이고, E2의 질문은
해상도 확장이 아니라 ERF 모양이다.

1. VOC 2012에서 고정 seed로 N장을 뽑는다. 224² center crop, ImageNet 정규화.
2. 이미지마다: forward → **최종 특징맵 중심 토큰의 채널 합** `s`를 만든다 →
   `s.backward()` → 입력 gradient 절댓값을 RGB로 합산해 224×224 맵을 얻는다.
3. 맵을 이미지별로 최댓값 정규화한 뒤 누적 평균한다. Luo et al.의 절차이며,
   한 장의 큰 gradient가 평균을 지배하는 것을 막는다.
4. 결과는 모델당 224×224 ERF map 하나.

짝수 격자(DeiT·Vim의 14×14)에서 "중심"은 네 칸 중 하나다. `(H//2, W//2)`로
고정한다 — 어느 쪽을 고르든 결론은 같지만, 정하지 않으면 재현이 안 된다. CMT의
최종 격자는 7×7이라 중심이 유일하다.

채널 합을 쓰는 이유는 특정 채널을 고르는 임의성을 없애기 위함이다. 중심 토큰이
"어디를 보는가"는 채널 선택과 무관해야 한다.

### 조건 세 가지

모델마다 아래 세 조건을 돌린다. 앞의 둘은 입력이 다르고, 셋째는 가중치가 다르다.

| 조건 | 목적 |
|------|------|
| 학습 가중치 + VOC 자연 이미지 | 본 결과 |
| 학습 가중치 + 가우시안 노이즈 | 이방성이 **구조**에서 오는지 **내용**에서 오는지 분리 |
| 랜덤 초기화 + VOC 자연 이미지 | 파이프라인 검증 (아래 정직성 장치) |

노이즈 대조군이 필요한 이유는 attention과 SSM이 **내용 적응적**이기 때문이다.
Luo et al.의 원 대상인 CNN은 ERF가 입력에 거의 무관했지만, 여기서는 그 가정이
성립하지 않는다. 자연 이미지에서만 재면 "구조가 만든 이방성"과 "이미지가 만든
이방성"을 구분할 수 없다.

## 지표

ERF map을 합이 1인 2D 분포 `A(p)`로 정규화한 뒤:

- **비등방 지수** = `√(λ_max / λ_min)`.
  `μ = Σ A(p)·p`, `Σ = Σ A(p)(p−μ)(p−μ)ᵀ`의 고윳값. 등방이면 1.0.
- **주축 각도** = 최대 고유벡터와 수평축 사이 각도, [0°, 90°].
  비등방 지수가 1에 가까우면 이 값은 의미가 없으므로 함께 보고한다.
- **수직/수평 감쇠율 비** = `s_v / s_h`.
  중심을 지나는 수평 프로파일 `h(d)`와 수직 프로파일 `v(d)`를 양쪽 평균으로 만들고,
  `log` 스케일에서 `d ∈ [1, 64]`에 선형 회귀한 기울기의 비. 1보다 크면 수직이
  더 가파르다 — 논문 3.1절의 예측 방향이다.

### 수렴 곡선

세 지표를 `N ∈ {16, 32, 64, 128, 256, 512}`에서 각각 계산해 CSV에 남긴다(512는
Task 9 리뷰에서 추가됐다 — 최초 5개 N으로는 `decay_ratio`가 계획 자체의 수렴
기준을 만족하지 못하는 셀이 있었다). 마지막 두 점 사이 상대 변화가 5%를 넘으면
그 지표는 아직 수렴하지 않은 것이고, **수렴하지 않은 값은 논문에 인용하지
않는다.** 세 지표는 각각 독립적으로 수렴 여부를 판단한다 — 하나가 수렴해도
다른 지표가 계속 움직일 수 있다. N을 늘려야 하는지 결과가 스스로 말하게 한다.

## 정직성 장치

E1에서 가장 비쌌던 실패는 아무것도 깨지지 않은 것처럼 보이는 오답이었다
(fvcore가 fused 커널을 조용히 0으로 셈). E2의 대응물은 **cls 토큰 오인**이다.

중심 패치 토큰 대신 cls 토큰의 gradient를 받으면 ERF가 이미지 전체에 고르게
퍼져서 비등방 지수 ≈ 1.0, 즉 **"완벽한 등방"이라는 그럴듯한 오답**이 나온다.
Vim은 cls 토큰이 시퀀스 *중앙*에 있어서(Vim의 middle cls 설계) 인덱스 계산이
특히 틀리기 쉽고, 하필 그 오류가 논문 주장을 반증하는 방향으로 틀린다.

이에 대한 가드는 셋이다.

1. **토큰 인덱스 → 입력 좌표 매핑을 테스트로 고정한다.** 모델마다 격자가 다르다
   (DeiT·Vim 14×14 패치 + cls, CMT 4-stage 7×7). 중심 토큰의 인덱스를 계산하는
   함수를 모델별로 분리하고, cls 토큰 위치를 명시적으로 배제한다.
2. **랜덤 초기화 대조**가 이 오류를 직접 잡는다. 학습되지 않은 모델의 ERF는
   Luo et al.이 보고한 대로 좁아야 한다. cls 토큰을 잡고 있었다면 랜덤 초기화에서도
   ERF가 넓게 나온다. 게이트는 절대 임계값이 아니라 **비교**로 건다 — 랜덤 초기화의
   질량 50% 반경이 학습된 모델보다 작을 것, 그리고 ERF 피크가 중심 토큰이 덮는
   패치 안에 있을 것. (E1의 교훈: 달성 불가능한 절대 기준을 걸면 가드를 푸는
   방향으로 가게 된다.)

   **피크 위치 기준(중심 토큰이 덮는 패치 안)은 `natural`과 `random_init`에만
   적용한다.** `noise`(사전학습 가중치 + `torch.randn` 입력)는 학습 분포 밖
   입력이다. Task 9 실측에서 `cmt_s`가 `noise` 조건에서만 ERF 피크가 이미지
   모서리(중심에서 ~110px)로 튀는 현상이 5개 표본 크기 전부에서 재현됐다 —
   그런데 같은 `cmt_s`의 `natural`·`random_init`은 전부 멀쩡했다. 프로브의 인덱스
   매핑이 틀렸다면 조건과 무관하게 항상 틀려야 하므로(가드 1이 이미 그 경로를
   막는다), 이건 프로브 결함이 아니라 **분포 밖 입력에서 conv+BatchNorm 아키텍처가
   보이는 실제 반응**으로 본다. 따라서 `noise`의 피크 이탈은 정직성 게이트를
   실패시키는 사유가 아니라 그 자체로 기록할 측정 결과다. 랜덤 초기화 대조(질량
   반경 비교)는 세 조건 중 여전히 `natural` vs `random_init`으로만 걸리므로 이
   범위 축소와 무관하게 그대로 유지한다.
3. **체크포인트 로딩 게이트.** `load_state_dict(strict=True)`로 missing/unexpected
   키가 0개여야 하고, 자연 이미지에 대한 로짓 엔트로피가 랜덤 초기화보다 낮아야
   한다. 부분 로드된 모델은 예외 없이 조용히 랜덤 모델처럼 행동한다.

## 새로 필요한 것

### 체크포인트 로딩 (선행 작업)

`build_model(pretrained=True)`는 현재 세 모델 모두 막혀 있다. E1이 연산량만 재서
가중치를 E2/E3로 미뤘기 때문이다.

| 모델 | 출처 |
|------|------|
| DeiT-S | timm (`deit_small_patch16_224`) |
| CMT-S | ggjy/CMT.pytorch GitHub Releases |
| Vim-S | hustvl/Vim (HuggingFace) |

체크포인트는 `checkpoints/`에 받고 git에 넣지 않는다(이미 `.gitignore`에 있다).
받은 파일의 SHA256을 `results/e2/env.json`에 기록해, 나중에 다른 가중치로 잰
결과와 섞이지 않게 한다.

### 데이터

`data/voc.py` — VOC 2012 trainval(약 2GB)을 `data/`에 받고, 고정 seed로 N장을
샘플한다. E3가 같은 이미지의 분할 마스크를 쓰므로 E2·E3가 데이터셋을 공유한다.
샘플된 파일 목록을 `results/e2/images.txt`에 남긴다 — 어떤 이미지로 잰 값인지
없으면 재현이 불가능하다.

|------|------|

### `.gitignore` 예외

지금 `results/**/*.npy`가 제외돼 있는데, 이는 "중간 산출 텐서 덤프"를 겨냥한
규칙이었다. **ERF map은 E2의 1차 측정값이다.** 그림이 커밋된 원시 데이터에서
생성돼야 한다는 이 저장소의 원칙을 지키려면 `results/e2/erf_maps.npz`를 예외로
허용해야 한다. 3모델 × 3조건 × 224² float32 ≈ 1.2MB.

## 테스트 전략

E1과 같다. **테스트가 자기가 막는다고 주장하는 회귀를 넣었을 때 실제로 실패하는지**
확인한다. E1 Task 12에서 회귀를 주입했더니 테스트 3건이 그대로 통과한 전례가 있다.

- 지표 계산은 합성 맵으로 검증한다. 등방 가우시안 → 지수 1.0, 수평으로 늘인
  가우시안 → 지수 > 1이고 주축 0°. matplotlib을 거치지 않는다.
- 중심 토큰 인덱스는 모델별로 테스트한다. cls 토큰을 집으면 실패해야 한다.
- 수렴 판정은 순수 함수로 분리해 직접 검증한다.

## 범위 밖

- **단계별 ERF 성장 곡선** — 비교 축이 늘어나 그림과 해석이 복잡해진다. 최종
  출력 중심 토큰 하나만 본다.
- **224² 외 해상도** — 사전학습 가중치가 유효한 지점에서만 잰다.
- **E3의 effective attention 환원** — 별도 계획.
