# E4 — 2×2 요인 학습 ablation 설계

작성 2026-08-25. 상위 설계는 `docs/superpowers/specs/2026-08-18-cmt-vs-vim-experiments-design.md`의
"E4 — 통제 학습 ablation" 절이며, 이 문서는 그것을 실행 가능한 수준까지 좁힌다.
상위 문서와 어긋나는 곳은 이 문서가 우선하고, 어긋난 이유를 각 절에 적었다.

## 검증 대상

논문 3.3절의 두 문장이다.

1. "차이의 대부분은 CMT가 주입한 2D 지역성과 multi-scale이라는 inductive bias에서
   발생한다"
2. "Vim에 동등한 구조적 prior를 주입한 후속 모델에서는 격차가 1%p 미만으로 좁혀진다"

두 문장 모두 현재 논문에서는 **인용**이다. 1은 CMT 원논문이 자기 모델 내부에서만
뜯어본 ablation이고, 2는 VMamba·LocalMamba 보고치다. 같은 구조적 prior가 SSM 쪽에서도
같은 효과를 내는지는 어느 쪽도 직접 확인하지 않았다. 2×2 요인 설계가 이를 분리한다.

## 요인 구조

|  | 평면 | 계층 + conv locality |
|---|---|---|
| **Attention** | A. DeiT-Ti | C. CMT-Ti |
| **SSM** | B. Vim-Ti | D. Hierarchical Vim |

```
구조 주효과   = (C+D)/2 − (A+B)/2
연산자 주효과 = (A+C)/2 − (B+D)/2
상호작용      = (D−B) − (C−A)
```

**상호작용이 이 실험의 목적이다.** 양수면 계층 구조가 SSM에 더 큰 이득을 준다는
뜻이고, 이는 논문이 인용으로만 처리한 격차 축소를 본인 실험으로 뒷받침한다.

### 요인 정의의 한계 — 상위 설계에서 그대로 가져온다

C의 CMT-Ti는 DeiT-Ti와 계층 구조만 다른 것이 아니다. LPU의 depth-wise conv, IRFFN의
conv locality, LMHSA의 K/V 축소가 함께 들어온다. 따라서 "구조 주효과"는 순수한 계층
효과가 아니라 **"CMT식 구조적 prior 묶음(계층 + conv locality)"의 효과**다. 분리하려면
2×2×2 = 24 run이 필요해 예산을 넘는다. 논문에 한계로 명시한다.

이 정의가 D의 구성을 강제한다. 상호작용이 의미를 가지려면 B→D 조작이 A→C와 같아야
하므로, D도 계층화와 conv locality를 **함께** 넣는다.

## 네 칸의 구성

데이터셋은 Tiny-ImageNet(200 클래스, 64×64, train 100k / val 10k)이다. CIFAR-100을
쓰지 않는 이유는 상위 설계에 있다 — 32×32를 patch 8로 자르면 토큰이 16개뿐이다.

| 칸 | 모델 | 토큰 구성 | 출처 |
|---|---|---|---|
| A | DeiT-Ti (폭 조정) | patch 8 → 8×8 = 64 | timm `deit_tiny_patch16_224`, `img_size=64` |
| B | Vim-Ti (스톡) | patch 8 → 8×8 = 64 | 벤더링된 `models/vim_official.py` |
| C | CMT-Ti (폭·depth 조정) | stem/2 후 16→8→4→2 | 벤더링된 `models/cmt_official.py` |
| D | Hierarchical Vim | C와 동일 격자 | 신규 `models/hvim.py` |

### D는 C에서 연산자만 바꾼 것이다

stem, patch merge, LPU, IRFFN, depths, stage 격자를 C와 공유하고 **LMHSA 자리에만**
Vim의 양방향 Mamba(`bimamba_type="v2"`)를 넣는다. 이 구성의 근거는 대칭성이다 — D−C가
"계층 안에서의 순수 연산자 효과"가 되고, B→D와 A→C가 같은 조작이 된다.

**단, 폭은 C와 공유하지 않는다.** LMHSA 블록과 Mamba 블록의 파라미터 수가 다르므로,
폭까지 같게 두면 D의 파라미터가 C와 어긋나 아래 "파라미터 예산"의 통제가 깨진다.
둘 중 하나만 성립하며, **파라미터 예산 정렬을 우선한다** — 용량 교란을 없애는 것이
이 실험에서 폭 조정을 하는 이유 자체이기 때문이다.

따라서 D는 자기 폭을 따로 맞춰 6.86M ±5%에 넣고, **C와 D의 실제 폭 차이를
`results/e4/README.md`에 값으로 보고한다.** D−C를 인용할 때 "연산자 교체 + 폭 차이
Δ"임을 함께 적고, 폭만 단독으로 인용하지 않는다.

VMamba식 4방향 scan은 쓰지 않는다. B(Vim-Ti)가 양방향이므로 D를 4방향으로 만들면
B→D가 "계층 + conv + scan 방향수"를 한꺼번에 바꾸게 되어 A→C와 조작이 달라지고,
상호작용 항에 scan 방향 효과가 섞인다. VMamba·LocalMamba는 인용하되, D는 신규 제안이
아니라 **요인 분리를 위한 통제된 재구현**임을 논문에 명시한다.

### 계층 격자는 stem stride 2를 유지한다

64px 입력에서 stage 격자가 16→8→4→2가 된다. **stage 2의 8×8이 평면 칸의 8×8과
정확히 일치**하는 것이 이 선택의 근거다. stem stride를 1로 풀면 격자가 32→16→8→4로
올라가 정렬은 더 좋아지지만 C·D 비용이 약 4배가 되어 예산을 넘는다(아래 "예산" 참고).

**최종 stage가 2×2 = 4토큰뿐이라는 점은 한계로 명시한다.**

### depth는 `[2,10,2,2]`로 재배치한다 — 스톡 `[2,2,10,2]`에서 벗어난다

CMT 스톡 depths는 16개 블록 중 10개를 stage 3에 둔다. 64px에서 stage 3 격자는
4×4 = **16토큰**이다(224px에서 같은 자리가 196토큰이다). 즉 모델의 본체가 12배 짧아진
시퀀스에서 돌게 되고, D의 SSM은 16스텝 recurrence로 사실상 아무것도 누적하지 못한다.
이 상태에서 상호작용이 0으로 나오면 "효과가 없다"와 "효과가 날 자리가 없었다"가
구분되지 않는다.

depth를 stage 2로 옮기면 본체가 8×8 = **64토큰**이 되어 평면 칸과 같은 시퀀스 길이가
된다. 비용은 실측으로 거의 중립이다 — CMT는 격자가 절반이 될 때 채널이 두 배라
블록당 FLOPs가 stage마다 거의 같다.

| CMT-Ti @64px | 본체 격자 | params | img/s | run당(300ep) |
|---|---|---|---|---|
| 스톡 `[2,2,10,2]` | 4×4 = 16 | 10.55M | 3186 | 2.6h |
| 재배치 `[2,10,2,2]` | 8×8 = 64 | 7.58M | 2700 | 3.1h |

재배치는 C와 D에 **동일하게** 적용되므로 요인 대비에는 영향이 없다. 공표된 CMT
depth 분포에서 벗어난다는 사실은 configs와 `results/e4/README.md`에 남긴다.

### 파라미터 예산 — Vim-Ti의 6.86M을 기준점으로 ±5%

스톡 설정은 정렬되어 있지 않다. 64px·200클래스에서 실측한 값이다.

| 칸 | 스톡 params |
|---|---|
| A DeiT-Ti (patch 8) | 5.43M |
| B Vim-Ti (patch 8) | 6.86M |
| C CMT-Ti (스톡 depths) | 10.55M |

C가 A의 1.94배다. 이대로 돌리면 구조 주효과에 용량 차이가 섞여 3.3절 주장의 근거로
쓸 수 없다. 따라서 **B의 6.86M을 기준점으로 네 칸을 ±5%에 맞춘다.** depth 재배치가
이미 C를 7.58M으로 내리므로 남은 조정 폭은 작다.

폭 탐색은 학습 없이 파라미터 카운트만으로 하고(수 분), 확정된 값은
`configs/e4_<cell>.yaml`에 고정한다. A·C·D는 공표된 설정이 아니게 되므로 문서와
논문에서 `DeiT-Ti(폭 216)`처럼 **조정 사실을 이름에 단다.** 공표 수치와 직접 비교하지
않는다.

## 학습 레시피

네 칸에 완전히 동일하게 적용하고 `configs/e4_common.yaml`에 고정한다.

```
입력 64×64,  batch 256,  epochs 300,  AMP fp16
AdamW,  lr 2.5e-4 (= 5e-4 × 256/512),  cosine,  warmup 5 epochs,  wd 0.05
label smoothing 0.1,  mixup 0.8,  cutmix 1.0,  drop path 0.1
RandAugment rand-m9-mstd0.5-inc1,  random erasing 0.25
EMA 없음
```

**upstream 레시피에서 벗어나는 곳은 두 군데다.** 변경 사실을 configs와 README에
남긴다. 둘 중 하나만 네 칸에 완전히 중립이며, 나머지 하나가 어느 칸에 걸리는지를
아래에 명시한다.

1. `RandomResizedCrop`의 `scale`을 `(0.08, 1.0)` → `(0.6, 1.0)`으로 올린다. 64px에서
   8%까지 잘라내면 남는 것이 5×5 픽셀이라 라벨이 무의미해진다. 네 칸에 같은 변환이
   걸리고 칸마다 다른 파라미터가 개입하지 않으므로 요인 비교에 남는 영향이 없다.
2. B·D의 mamba `A_log`·`A_b_log`가 weight decay에서 빠진다. `bench/train.py`의
   `param_groups`는 세 조건의 합집합(rank < 2, `model.no_weight_decay()`의 이름,
   `param._no_weight_decay` 표식)을 네 칸에 글자 그대로 같은 규칙으로 적용한다.
   그 결과 **A·C의 제외 집합은 DeiT 원 레시피와 정확히 같아진다** — DeiT·Vim의 원
   스크립트가 쓰는 timm `create_optimizer` → `param_groups_weight_decay(model, wd,
   model.no_weight_decay())`와 같은 분할이다. 남는 차이는 세 번째 조건이다: timm의
   그 함수는 `_no_weight_decay` 표식을 보지 않아 `A_log`·`A_b_log`(rank 2)를
   decay하지만, 이 저장소는 mamba upstream이 단 표식을 따라 뺀다
   (`mamba_ssm/modules/mamba_simple.py`). `A = -exp(A_log)`이라 decay가 SSM의
   시간상수를 미는 것을 막으려고 존재하는 표식이기 때문이다. 그런 파라미터는 B·D에만
   있으므로 **이 한 가지는 연산자 주효과 축에만 걸리는 편차다**. 방향은 "SSM 쪽이
   upstream 의도대로 정규화된다"이며, Vim 원 스크립트와 비교했을 때의 차이다.

   **이 상쇄는 근사다.** 대수적으로는 B와 D에 같은 크기 δ가 얹히면 구조 주효과와
   상호작용 항에서 δ가 지워지고 연산자 주효과에만 남는다. 그런데 마킹되는
   `A_log`·`A_b_log` 개수가 B(평면, depth 24) 48개, D(계층, depth 16) 32개로
   깊이가 다르므로 δ_B = δ_D가 정확히 성립할 이유는 없다. 즉 구조 주효과·
   상호작용 항에도 작은 잔차가 남을 수 있다 — 0이 아닐 수 있다는 뜻이지, 크다는
   뜻은 아니다.

이전 판은 두 번째 편차를 "`pos_embed`·`cls_token`이 decay를 받는다(A·B에만 걸린다)"로
적었다. `param_groups`가 `model.no_weight_decay()`를 읽게 되면서 그 편차는 사라졌다.

EMA를 쓰지 않는 이유는 메모리·시간 비용이 네 칸에 비대칭으로 걸리기 때문이다.

## 사전 등록 예측

**측정 전에 확정하며, 측정 후에 고치지 않는다.** 빗나가면 빗나간 대로 적는다.

| # | 예측 | 근거 |
|---|---|---|
| 1 | 구조 주효과 > 0 | 논문 3.3절 "차이의 대부분은 구조적 prior에서" |
| 2 | **상호작용 > 0** | 계층이 SSM에 더 큰 이득 — 논문이 인용으로만 처리한 부분 |
| 3 | 평면에서 A > B, 계층에서 C와 D의 차이가 1%p 미만 | 논문의 "격차 1%p 미만으로 좁혀진다" |
| 4 | 네 칸 모두 45~60% top-1 | 관문 2의 sanity 대역 (예측이 아니라 검증 범위) |

예측 4는 과학적 주장이 아니라 파이프라인 검증용 대역이다. 벗어나면 숫자를 쓰기 전에
원인을 규명한다.

## 검증 관문

측정 도구가 틀렸으면 나머지가 무의미하다. 상위 설계는 E4의 관문을 "Vim-Ti / DeiT-Ti
체크포인트 ImageNet 재평가(76.1% / 72.2%)"로 정했으나, **이 문서는 그것을 쓰지
않는다.** ImageNet val 6.7GB가 이 저장소에 없고, 더 중요하게는 그 관문이 평가 경로만
검증하고 **학습 루프는 건드리지 않기** 때문이다. E4에서 조용히 틀릴 곳은 학습 쪽이다.

**관문 1 — overfit-200 (칸당 약 3분).** 네 칸 각각이 200장 부분집합을 학습 정확도
95% 이상으로 외우는지 확인한다. augmentation과 mixup을 끈 상태로 돌린다. 실패하면
그 칸의 본 학습을 시작하지 않는다.

이 관문이 막는 것: 라벨 매핑 어긋남, lr 폭주, 얼어붙은 파라미터, augmentation이
라벨과 어긋나는 경우, D칸 배선 오류.

**관문 2 — A칸 최종 top-1이 예측 4의 대역 안인가.** 벗어나면 네 칸의 숫자를 쓰기 전에
원인을 규명한다.

## 파이프라인

| 파일 | 책임 | 조용히 틀릴 지점 |
|---|---|---|
| `data/tiny_imagenet.py` | 다운로드·무결성·라벨 매핑 | **val은 `val_annotations.txt` 구조라 `ImageFolder`로 읽으면 라벨이 통째로 어긋난다.** train/val 클래스 순서 일치를 테스트로 못박는다 |
| `models/hvim.py` | D칸 | C와 공유해야 할 부분이 갈라지는 것 |
| `models/registry.py` | 네 칸 build, 폭 고정 | 폭이 configs와 어긋남 |
| `bench/train.py` | 학습 루프, AMP, 스케줄, 재개 | 재개 시 lr 스케줄·RNG가 리셋되는 것 |
| `experiments/e4_ablation.py` | 12 run 오케스트레이션 | run 도중 실패 시 앞선 run까지 잃는 것 |
| `figures/e4_plot.py` | 2×2 표 + 학습곡선 | 결측 run을 감추는 것 |

**재개는 선택이 아니다.** 최장 run이 약 15시간이고 GPU를 다른 용도로도 쓴다. epoch마다
체크포인트를 쓰고 재시작 시 model·optimizer·scheduler·epoch·RNG 상태를 모두 이어받는다.
체크포인트는 git에 넣지 않는다.

**run마다 CSV를 다시 쓴다.** E1에서 배운 것이다 — 마지막에 한 번만 쓰면 중간 실패가
앞선 결과를 전부 지운다. 실패한 run은 `status="error"` 행으로 남긴다.

### 실행 순서

**seed 1의 네 칸을 먼저 전부 돌린다**(약 33시간). 2×2 표가 한 번 완성되어 조기에
신호를 본다. 그다음 seed 2, seed 3. 시간이 모자라면 seed 2까지로도 요인 설계가
성립한다.

## 예산

RTX 3070 Ti에서 학습 스텝 처리량을 실측해 산출했다(AMP fp16, batch 256, 300ep × 100k).

| 칸 | 토큰 | img/s | run당 | seed 3개 |
|---|---|---|---|---|
| A DeiT-Ti | 64 | 5436 | 1.5h | 4.5h |
| B Vim-Ti | 64 | 579 | 14.4h | 43.2h |
| C CMT-Ti (재배치) | 본체 64 | 2700 | 3.1h | 9.3h |
| D H-Vim | 본체 64 | 미측정 | 약 14h(추정) | 약 42h |
| | | | **합** | **약 99h ≈ 4일** |

D는 구현 전이라 추정치다. **같은 토큰 수에서 Vim이 DeiT보다 9배 느리다** — 예산은
B·D 두 SSM 칸이 전부 결정한다.

### 폴백 트리거 — 미리 못 박는다

D 구현 직후 처리량을 실측하고, 12 run 총합 추정이 **120시간을 넘으면 seed 3→2**로
줄인다. 그래도 넘으면 **epochs 300→200**으로 줄인다. **칸은 절대 줄이지 않는다** —
하나라도 빠지면 요인 설계가 무너진다.

## 테스트 전략

E1~E3와 같은 기준을 적용한다 — **이 테스트는 자기가 막는다고 주장하는 회귀를 넣었을 때
실제로 실패하는가.**

- `data/tiny_imagenet.py`: val 라벨 매핑이 train과 일치하는지. 매핑을 일부러 섞으면
  실패해야 한다.
- `models/hvim.py`: D의 stage 격자와 depths가 C와 같은지 직접 대조하고, 폭은 C와
  같은지가 아니라 **파라미터가 예산 대역 안인지**로 검사한다. 한쪽만 바꾸면 실패해야
  한다.
- `bench/train.py`: 재개가 lr 스케줄과 epoch을 이어받는지. 체크포인트에서 스케줄러
  상태를 빼면 실패해야 한다.
- `experiments/e4_ablation.py`: run 중간 실패가 앞선 run의 CSV 행을 남기는지.
- `figures/e4_plot.py`: 결측 run이 그림에서 0이나 빈칸으로 사라지지 않는지.

그림에 그려지는 문자열은 전부 영어로 둔다(matplotlib 기본 폰트에 한글 글리프 없음).
CSV의 범주 값도 ASCII로 둔다. `error` 열과 Markdown 산문은 한글이어도 된다.

## 논문에 명시할 한계

1. "구조 주효과"는 계층 + conv locality 묶음의 효과이며 순수 계층 효과가 아니다.
2. 계층 칸의 최종 stage가 2×2 = 4토큰뿐이다.
3. 시퀀스가 64토큰이라 **SSM의 긴 시퀀스 이점은 드러나지 않는다.** 128px로 올리면
   평면 칸이 256토큰이 되어 이 부분이 살아나지만 12 run이 약 312시간(13일)이 되어
   예산을 넘는다. 이 실험의 결론은 짧은 시퀀스 영역의 것이다.
4. 네 칸이 폭 조정 모델이므로 공표 수치와 직접 비교할 수 없다. C·D는 depth 분포도
   공표 설정과 다르다. 또한 C와 D는 파라미터를 맞추느라 폭이 서로 다르므로, D−C는
   "연산자 교체 + 폭 차이"이며 순수한 연산자 효과가 아니다.
5. **B→D 조작이 A→C 조작과 norm 종류·잔차 정밀도에서 다르다.** B(Vim-Ti)는
   `rms_norm=True`, `fused_add_norm=True`, `residual_in_fp32=True`로 만들어지는데
   (Vim은 fp16 안정성을 위해 `residual_in_fp32`를 쓴다), D는 C의 골격을 상속하므로
   블록이 `nn.LayerNorm`을 쓰고 잔차가 fp16으로 흐른다. 즉 A→C는 LayerNorm →
   LayerNorm인 반면 B→D는 RMSNorm + fp32 잔차 → LayerNorm + fp16 잔차다. "D는 C의
   골격을 공유한다"는 설계에서 직접 나오는 제약이라 코드로 없앨 수 없고 — 없애면 D가
   C의 골격을 벗어나 구조 요인 자체가 흐려진다 — 위 4번의 폭 차이와 같은 종류의
   잔여 비대칭으로 논문에 적는다.
6. Tiny-ImageNet 결과를 ImageNet으로 외삽하지 않는다.

## 범위 밖

- conv locality를 세 번째 요인으로 분리하는 것(2×2×2 = 24 run, 예산 초과)
- ImageNet 학습 또는 사전학습 가중치를 쓴 fine-tuning
- D를 신규 아키텍처로 제안하는 것
- 128px 이상의 해상도

## 리스크

| 리스크 | 대응 |
|---|---|
| D 구현이 예상보다 무겁다 | 관문 1(overfit-200)에서 조기에 드러난다. 처리량 실측 후 폴백 트리거 적용 |
| 12 run 중간에 GPU를 뺏긴다 | epoch 단위 체크포인트 + 재개. run별 CSV 즉시 기록 |
| 세 seed의 분산이 효과 크기보다 크다 | 그 자체가 결과다 — "효과가 seed 분산에 묻힌다"로 보고하고 숨기지 않는다 |
| 폭 정렬이 ±5%에 안 들어온다 | 실제 달성한 정렬 폭을 보고하고, 남은 차이를 한계로 적는다 |
